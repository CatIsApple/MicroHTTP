## 핵심 개념 정리

### 정적 파일 응답 흐름
- 핵심: 파일 바이트를 소켓 fd에 그대로 씀. 클라는 `Content-Type` 보고 해석.
- 순서: URI → 파일 경로 → `open` + `fstat`(크기) → 응답 머리(`Content-Type`, `Content-Length: st_size`) → 머리 send → 본문 send → `close(file_fd)`.
- `Content-Length`를 머리에 먼저 써야 하므로 크기를 먼저 알아야 함 → `fstat`.
- `fstat`은 경로가 아니라 **연 fd**에 대고 함 → 확인과 사용 사이 파일 바뀌는 문제(TOCTOU) 회피.

### 파일 내용 보내는 3가지 방법
| | 복사 | 메모리 | 이식성 | 난이도 |
|---|---|---|---|---|
| A. read/send 반복 | 2번 (파일→커널→유저→커널→소켓) | 청크(64KB)만큼 | ◎ POSIX | 쉬움 |
| B. mmap | 1번 | 가상 매핑 | ○ POSIX | 중간 |
| C. sendfile | 0번 (커널 안) | 거의 0 | △ OS별 시그니처 다름 | 중간 |
- A: `while ((n = read(fd, chunk, 65536)) > 0) tcp_send_all(...)`. 1GB도 메모리 64KB.
- B: `mmap` 결과를 `tcp_send_all2(head, p)`에 넘김. 주의: 크기 0 파일은 mmap 실패, 보내는 중 파일 잘리면 SIGBUS.
- C: Linux `sendfile(sock, file, &off, len)` / macOS `sendfile(file, sock, off, &len, hdtr, 0)` → `#ifdef` 필요. nginx가 씀.
- 금지: 파일 전체 `malloc` 후 read → send. 큰 파일·동시 요청에 메모리 폭발.

### sendfile 성능 다듬기 (이번 구현)
- **MSG_MORE (Linux)**: 머리를 `MSG_MORE`로 커널에 맡겨 두고 sendfile → 머리+본문이 같은 패킷. 안 하면 작은 머리 패킷이 따로 나가고, 파일 끝 조각이 Nagle + 지연 ACK(최대 40ms) 대기.
- **macOS hdtr**: `sf_hdtr.headers`에 머리 실어 시스템콜 하나. EAGAIN이어도 `*len`에 "머리 포함 보낸 바이트" 옴. 입력 `len == 0`은 "파일 끝까지" 뜻이라 len>0일 때만 호출. TCP 아닌 소켓(socketpair)은 아무것도 안 보냈을 때 pread 경로로 폴백.
- **sendfile은 MSG_DONTWAIT 플래그 없음** → 소켓 자체가 논블로킹이어야 마감 시간 지킴. `accept4(SOCK_NONBLOCK | SOCK_CLOEXEC)`로 처음부터 논블로킹 → 응답마다 fcntl 2번 제거.
- **CLOEXEC**: 나중에 CGI fork+exec 때 자식에게 연결 소켓·파일 fd 안 새게.
- **낙관적 send**: 먼저 `sendmsg` 시도 → EAGAIN일 때만 `poll`. 송신 버퍼는 거의 비어 있어서 매번 poll 먼저 하면 시스템콜 낭비.
- **MSG_NOSIGNAL**: 끊긴 소켓에 써도 SIGPIPE 대신 EPIPE.
- **idle 타임아웃**: 파일 송신은 "전체 5초" 대신 "진척 없음 5초". 전체 기준이면 느린 회선에서 큰 파일 영원히 못 받음. 대가: 느리게 읽는 클라가 반복 서버를 오래 붙잡음(리뷰에서 지적됨).
- 측정(WSL 루프백, 1GB): sendfile 0.12s ≈ 8.7GB/s / pread 폴백 0.22s ≈ 4.7GB/s.

### 경로 해석 / 보안 (`static_resolve`)
- `?` 쿼리, `#` 조각 버림. absolute-form(`http://host/a`)은 authority 건너뜀.
- `%XX` 디코딩을 **먼저** 하고 검사 → `%2e%2e` 우회 차단. `%2F`도 `/`로(nginx와 같음). `%00` → 400(`a.php%00.png` 류 우회 차단).
- 세그먼트 정리: `//`·`.` 건너뜀, `..`는 앞 세그먼트 제거, 루트보다 위로 가면 403.
- 숨김 파일(`.git`, `.env`, `.htpasswd`) → 403, `.well-known`만 허용.
- 끝이 `/`(또는 `.`/`..`) → `index.html` 붙임.
- 처음 설계: `realpath()` + 루트 prefix 비교 → 실제 구현: 시작 때 루트를 `open(O_DIRECTORY)`로 한 번 열고 요청마다 `openat(root_fd, rel)`. 요청마다 루트 재해석·realpath 비용 없음. `..`는 문자열 단계에서 차단.
- 심링크: 루트 안 심링크는 따라감(운영자가 둔 것으로 봄, nginx 기본과 같음). 리눅스 `openat2(RESOLVE_BENEATH)`는 이식성 없어 안 씀.

### 파일 열기와 상태 코드 (`static_lookup`)
- `openat` 플래그: `O_NONBLOCK`(루트 안 FIFO에서 open 멈춤 방지), `O_NOCTTY`, `O_CLOEXEC`.
- errno → 상태: `ENOENT`/`ENOTDIR`/`ENAMETOOLONG`/`ELOOP` → 404, `EACCES`/`EPERM` → 403, 그 외(EMFILE 등) → 500.
- 디렉토리 + 끝에 `/` 없음 → 301 `Location: <uri>/`(쿼리 유지). 이유: index.html 안 상대 링크(`a.css`)가 `/docs/a.css`로 풀리게.
- `index.html` 없는 디렉토리 → 404(목록 안 보여 줌). 일반 파일 아님(FIFO·장치) → 403.

### 조건부 GET (304)
- 200 응답에 `Last-Modified`(파일 mtime) 붙임 → 브라우저가 다음에 `If-Modified-Since`로 보냄 → 안 바뀌었으면 304, 본문 없음.
- `http_parse_date`: IMF-fixdate(`Sun, 06 Nov 1994 08:49:37 GMT`, 29글자)만. `timegm`은 POSIX 아님 → days_from_civil(Howard Hinnant)로 직접 계산.
- 해석 불가·미래 날짜(서버 시계보다 뒤) → 무시하고 200.
- 304는 Content-Length·Content-Type 생략.

### HEAD 메서드
- GET과 같은 머리(Content-Length = 파일 크기), 본문 없음. `curl -I`용. 범용 서버는 GET·HEAD 필수(RFC 7231 4.1).
- 구현: 파서에 `HTTP_METHOD_HEAD`, `http_response.head_only`, `http_send_error_ex(..., head_only, ...)`.

### MIME 매핑
- 마지막 `/` 뒤 파일 이름의 마지막 `.` 뒤 확장자, ASCII 소문자화(locale 영향 없게 직접), 정렬 표 `bsearch`.
- 텍스트 계열 `; charset=utf-8`(한글 깨짐 방지). `.js` → `text/javascript`(RFC 9239), `.wasm` → `application/wasm`(instantiateStreaming 필수), `.json`은 charset 불필요.
- 모르는 확장자·확장자 없음·`.bashrc`류 → `application/octet-stream`(브라우저는 다운로드).
