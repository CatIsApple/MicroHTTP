# HTTP 응답 코드리뷰 — 성능 / 구조 (vs 다른 구현)

범위: `CDH/` 브랜치 전체 (`CDH/WebServer` vs `main`). 초점 = 3단계 응답 (`http_response.c`, `tcp_send_all2`, `main.c` echo).
비교 대상: nginx, Apache httpd, lighttpd, Go `net/http`, CS:APP Tiny.

---

## 0. 한줄 결론

- 정확성 OK. 테스트 67개 통과, ASAN 깨끗.
- 성능 병목 1순위 = **매 요청 연결 종료 + 반복 서버**. 응답 코드 미세 최적화는 그 다음.
- 구조 병목 1순위 = **본문 = 메모리만**. 정적 파일 단계 오면 `sendfile` 못 씀 → 지금 손볼 것.

## 1. 성능

| # | 위치 | 지금 | 문제 | 다른 구현 | 개선 | 효과 |
|---|---|---|---|---|---|---|
| P1 | `main.c` 반복 루프 + `Connection: close` 고정 | 요청 1개 = TCP 연결 1개 | handshake 3번 + FIN 4번 + TIME_WAIT 매 요청. 느린 클라 1명 → 전원 대기 | nginx: epoll + keep-alive. Apache event MPM. Go: 연결당 goroutine + keep-alive 기본 | 동시성 단계에서 keep-alive 루프 + 이벤트 루프/스레드풀 | **최대**. `ab -k` 기준 수 배 |
| P2 | `tcp_close_graceful` drain | 안 읽은 바이트 있으면 최대 0.5s 대기 | 반복 서버라 잘못된 클라 1명 = 0.5s 전체 정지 | nginx `lingering_close` = 이벤트 루프 안 비동기 | 비동기 drain (이벤트 루프) 또는 스레드 분리 | 오류 폭주 시 큼 |
| P3 | `main.c:115` echo | `malloc(요약+본문)` → `memcpy` 2번 | 1MB POST → 1MB 추가 할당 + 복사. OOM 시 500 경로 생김 | nginx/lighttpd: 버퍼 체인 → `writev` 한 번. 복사 0 | `tcp_sendv_all(iov[], n)` 일반화 → `{head, summary, body}` 3조각 | 큰 POST 메모리 2배 → 1배 |
| P4 | `tcp_send_all`/`tcp_send_all2` | 매 루프 `poll` 먼저 → `send` | 송신 버퍼 비어 있어도 syscall 2번 (poll+send) | nginx: 그냥 `writev` 먼저, `EAGAIN` 때만 이벤트 대기 | `send` 먼저 시도 → `EAGAIN` 때만 `poll` | 응답당 syscall -1 (recv 쪽도 같음) |
| P5 | `http_send_response` `time(NULL)` + `gmtime_r` + `snprintf` | 응답마다 날짜 포맷 | 고RPS에서 미세 비용 | nginx `ngx_cached_http_time`: 초 단위 캐시. Go: 매번 `appendTime` (캐시 X) | 1초 캐시 (`static time_t last; static char cached[32]`) — 스레드풀 가면 스레드별 or 락 | 작음. 측정 후 결정 |
| P6 | `http_format_head` `snprintf` 1번 | 형식 문자열 매번 해석 | 미세 | nginx: 길이 먼저 계산 → `ngx_cpymem` 이어 붙이기 | 지금 유지 OK. 병목 아님 | 작음 |
| P7 | `http_reason` 선형 탐색 17개 | 최대 17 비교 | 무시 가능 | nginx: 상태코드 → 배열 인덱스 직행 | `switch` (컴파일러가 점프 테이블) | 작음 |

### 측정 순서 (추측 말고 재기)
1. `ab -n 10000 -c 1 http://127.0.0.1:8080/` → 기준선
2. keep-alive 붙인 뒤 `ab -k` 비교 → P1 효과
3. `strace -c ./microhttp` → syscall 수 (P4 효과 확인)
4. `perf record` → `gmtime_r`/`snprintf` 비중 (P5·P6 할지 판단)

## 3. 다른 구현 비교 (응답 송신 관점)

| 항목 | 우리 (지금) | CS:APP Tiny | nginx | Apache httpd | lighttpd | Go `net/http` |
|---|---|---|---|---|---|---|
| 머리 만들기 | `snprintf` 1번, 스택 1KB | `sprintf` 이어 붙이기 | 길이 계산 → pool 할당 → `cpymem` | 필터 체인이 버킷으로 | chunkqueue 에 append | `bufio.Writer` (4KB) 에 쓰기 |
| 머리+본문 송신 | `sendmsg` iov 2개, 복사 X | `write` 2번 (머리, 본문) | `writev` 체인 + `sendfile` | 버킷 brigade → `writev`/`sendfile` | `writev`/`sendfile` | bufio flush, 파일은 `sendfile` (`io.Copy` → `ReadFrom`) |
| 파일 본문 | 미지원 (메모리만) | `mmap` → `write` | `sendfile` (zero-copy) | `sendfile`/`mmap` | `sendfile` | `sendfile` |
| Date | 매번 `gmtime_r` | 없음 | 초 단위 캐시 | 캐시 | 캐시 | 매번 |
| 길이 모를 때 | 지원 X (CL 필수) | 지원 X | chunked | chunked | chunked | 작으면 CL, 크면 chunked 자동 |
| keep-alive | X (close 고정) | X | O | O | O | O (기본) |
| 동시성 | 반복 (1개씩) | 반복 | 이벤트 루프 (epoll) | prefork/worker/event MPM | 이벤트 루프 | goroutine/연결 |
| SIGPIPE | 전역 `SIG_IGN` | 책에서 `SIG_IGN` 권장 | `SIG_IGN` | `SIG_IGN` | `SIG_IGN` | 런타임이 처리 |
| 송신 타임아웃 | 응답 전체 deadline + poll | 없음 | `send_timeout` (연속 두 쓰기 사이) | `Timeout` | `max-write-idle` | `WriteTimeout` (전체 deadline) |

### 해석
- **Tiny → 우리**: `write` 2번 → `sendmsg` 1번 = Nagle 지연 제거. 타임아웃·헤더 주입 검사 추가. Tiny 보다 확실히 위.
- **우리 → nginx 사이 간격**: 3개뿐.
  1. 본문 출처 추상화 (메모리/파일) → `sendfile`
  2. iovec N개 (버퍼 체인)
  3. 이벤트 루프 + keep-alive
- 타임아웃 방식: 우리 = Go `WriteTimeout` 식 (전체 마감). nginx = 쓰기 사이 간격. 전체 마감이 slowloris(느린 읽기) 에 더 강함. 유지.

## 3.5 처리 현황 (2026-11-24)

| 항목 | 상태 | 어떻게 |
|---|---|---|
| S1 본문 = 메모리만 | ✅ | `http_response.use_file/file_fd/file_offset` 추가 → `tcp_sendfile_all` (리눅스 `sendfile`, 그 외 `pread`+send 64KB). 머리+파일 전체 마감 1개 |
| S2 송신 루프 2벌 | ✅ | `sendv_until` 1개. `tcp_sendv_all`·`tcp_send_all`·`tcp_sendfile_all` 전부 이걸 지남. `tcp_send_all2` 삭제 |
| P3 echo 복사 | ✅ | `iov[3] = {머리, 요약, 본문}` → malloc·memcpy 0 |
| S4 머리 버퍼 1024 | ✅ | `HTTP_HEAD_MAX 4096`. 2048자 `Location` 테스트 |
| S5 1xx/204/304 | ✅ | 1xx = 거절(-1). 204/304 = `Content-Length` 생략 + 본문 안 보냄. 이유 문구 204/301/304 추가 |
| S6 추가 헤더 검증 | ✅ | 줄마다 `이름: 값\r\n` 검사. 빈 줄·단독 CR/LF·이름 공백·제어문자 거절. `Content-Type` 도 제어문자 전부 거절 |
| S8 로그 2벌 | ✅ (덤) | `log_sent` 1개 |
| S3, S7, S9, P1, P2, P4~P7 | ⏳ | 안 건드림 |

테스트: `make test` 119 checks 통과. `-DMICROHTTP_NO_SENDFILE` 로 macOS 용 경로도 리눅스에서 통과.

## 4. 할 일 순서 (추천)

1. **S1 + S2** 지금: `tcp_sendv_all` + 본문 출처(fd) → 4단계 정적 파일 바로 `sendfile`. P3 도 같이 해결.
2. **S4 + S5 + S6** 4단계 시작 전: 리다이렉트·304 쓰기 전에 막아 둘 것.
3. **S7** 한 줄짜리. 아무 때나.
4. **P1 + P2** 동시성 단계: keep-alive + 이벤트 루프/스레드풀. 성능 체감 최대.
5. **P4 → P5 → P6/P7** 측정 후. 숫자 안 보이면 안 함.
6. **S3, S8, S9** 리팩터링. 기능 단계 사이 쉬는 타이밍.
